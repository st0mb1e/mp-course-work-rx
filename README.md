## 1. Введение и постановка задачи

Целью работы является создание учебной реализации RxJava: поток событий на базе паттерна "Наблюдатель", асинхронное выполнение с использованием планировщиков, операторы преобразования потока, обработка ошибок и модульное тестирование.

В проекте реализованы типы `Observable`, `Observer`, `Disposable`, интерфейс `Scheduler` и его имплементации, операторы `map`, `filter`, `flatMap`, методы `subscribeOn` и `observeOn`, а также набор модульных тестов.

## 2. Архитектура системы

### 2.1. Разбиение на пакеты

| `rx.core`       | Классы `Observable`, `Observer`, `Disposable`, механизм подписки                                                                             |

| `rx.operators`  | Классы `MapObservable`, `FilterObservable`, `FlatMapObservable`                                                                              |
| `rx.internal`   | Реализация `subscribeOn` и `observeOn`, класс `BooleanDisposable`, вспомогательные источники данных для конструкторов `from` и по `Iterable` |


### 2.2. Паттерн Observer

Интерфейс `Observer` задаёт приём уведомлений методами `onNext`, `onError` и `onComplete`.

Класс `Observable` хранит логику источника в виде объекта `OnSubscribe`: при подписке выполняется переданная при создании процедура, которая должна вызывать соответствующие методы у экземпляра `Observer`. Операторы оформлены как новые экземпляры `Observable`, оборачивающие исходный поток и передающие события следующему наблюдателю в цепочке.

### 2.3. Создание потоков данных

Для произвольного источника используется метод `Observable.create(OnSubscribe)`. Дополнительно реализованы перегрузки `create(Iterable)` и статический метод `from(...)` для удобства тестирования и демонстрации.

### 2.4. Подписка и отмена

Метод `subscribe(Observer)` возвращает объект `BooleanDisposable`. Перед вызовом `onNext` и `onComplete` проверяется флаг отмены подписки. После срабатывания `onError` или `onComplete` подписка завершается. Исключения, возникающие при вызове `source.subscribe`, перехватываются и передаются в `onError`.

Перегрузки `subscribe` с функциональными интерфейсами Java реализованы как обёртки над `Observer`.

### 2.5. Операторы

Оператор **map** применяет к каждому элементу функцию `mapper`. Исключения из метода `apply` направляются в `onError`.

Оператор **filter** передаёт дальше только элементы, для которых предикат возвращает истину. Исключения из метода `test` также приводят к вызову `onError`.

Оператор **flatMap** для каждого входного элемента получает вложенный `Observable` и подписывается на него. Для единственного вызова `onComplete` у внешнего наблюдателя применяется счётчик `AtomicInteger activeStreams`, учитывающий завершение исходного потока и всех внутренних потоков.

### 2.6. Методы subscribeOn и observeOn

Класс `SubscribeOnObservable` выполняет вызов `source.subscribe(observer)` в рамках задачи, поставленной в `scheduler.execute`, то есть подписка и запуск ленивого ("холодного") источника выполняются в пуле потоков выбранного планировщика.

Класс `ObserveOnObservable` подписывается на источник в текущем потоке, а доставку уведомлений `onNext`, `onError` и `onComplete` наблюдателю, следующему в цепочке, ставит в очередь планировщика через `scheduler.execute`.

Таким образом, `subscribeOn` определяет контекст выполнения подписки и источника, `observeOn` переносит обработку событий у нижележащего наблюдателя в заданный планировщик. По сравнению с полной реализацией RxJava данная схема намеренно упрощена.

## 3. Планировщики (Scheduler)

Планировщик отвечает за то, в каком потоке выполнится переданный ему `Runnable`. Сам `Observable` потоки не создаёт, а вызывает `scheduler.execute(...)`, а классы планировщиков пересылают задачу в `ExecutorService.submit(...)`.

```java
void execute(Runnable task);
```

Вызов не блокирует вызывающий код. У `SingleThreadScheduler` задачи выполняются в порядке постановки. У многопоточных пулов задачи могут идти параллельно, порядок завершения не фиксирован.

В цепочке планировщик используется только в `subscribeOn` и `observeOn` (см. п. 2.6). `subscribeOn` отправляет в пул весь вызов `source.subscribe(observer)` (у "холодного" источника с этого момента обычно начинается выдача событий), поэтому под него чаще берут пул ввода-вывода. `observeOn` подписывается наверху в текущем потоке, а каждый `onNext` / `onError` / `onComplete` для следующего наблюдателя ставит в `execute` уже выбранного планировщика, чтобы обработка шла в другом контексте.

Цепочка `subscribeOn(Schedulers.io()).observeOn(Schedulers.single())`: подписка на источник уходит в кэшируемый пул, элементы оттуда эмитятся, а финальный подписчик получает события в одном выделенном потоке. Тяжёлое ожидание обычно оставляют за `subscribeOn`, смену потока для дальнейшей логики делают через `observeOn` (например `single()` или `computation()`).

Экземпляры создаются через `Schedulers.io()`, `computation()`, `single()`. Соответствие реализаций и пулов:


| Класс                   | Пул                                       | Зачем                                                                               |
| ----------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------- |
| `IOThreadScheduler`     | `newCachedThreadPool()`                   | Ожидание сети, диска и т.п.: потоков может быть много, лишние со временем убираются |
| `ComputationScheduler`  | `newFixedThreadPool` по числу процессоров | Нагрузка на CPU без лишнего числа потоков                                           |
| `SingleThreadScheduler` | `newSingleThreadExecutor()`               | Одна очередь, предсказуемый порядок                                                 |


Ожидающие задачи плохо упаковываются в пул "по числу ядер" (потоки простаивают). Для CPU лишние потоки дают лишние переключения контекста, здесь уместен фиксированный пул. Нужна строгая очередь без параллели внутри одного планировщика, берут один поток.

В коде курсовой у каждого вызова фабрики свой `ExecutorService`. В настоящей RxJava пулы часто общие на всё приложение.

## 4. Обработка ошибок

Исключения, возникающие в пользовательских функциях операторов `map`, `filter` и `flatMap`, преобразуются в вызов `onError` у наблюдателя ниже по цепочке.

При подписке вызов источника обрамлён конструкцией `try`/`catch`. Необработанное исключение передаётся в `onError`.

Механизм `Disposable` предотвращает доставку событий после завершения потока или отмены подписки.

## 5. Тестирование

Модульные тесты выполнены с использованием JUnit 5 и размещены в каталоге `src/test/java/ru/yartsev_vladislav/rx/`.

Класс `ObservableTest` проверяет создание потока из массива и из итерируемой коллекции, вызов `onComplete` и `onError`, отсутствие элементов после ошибки, сочетание операторов `map` и `filter`, работу `subscribeOn` и `observeOn`, а также отмену подписки.

Операторы покрыты отдельными классами: `MapObservableTest`, `FilterObservableTest`, `FlatMapObservableTest`.

Для планировщиков и обёрток `SubscribeOnObservable` / `ObserveOnObservable` проверяется выполнение в многопоточной среде (в том числе использование различных потоков для `IOThreadScheduler` и одного потока для `SingleThreadScheduler`), порядок выполнения при необходимости. Для синхронизации тестов с асинхронными задачами применяется `CountDownLatch`.

Запуск тестов из корня проекта:

```bash
./gradlew test
```

## 6. Примеры использования

### Операторы map и filter

```java
Observable.from(1, 2, 3, 4, 5)
    .filter(n -> n % 2 == 0)
    .map(n -> "чётное: " + n)
    .subscribe(
        System.out::println,
        Throwable::printStackTrace,
        () -> System.out.println("готово")
    );
```

### Оператор flatMap

```java
Observable.from("a", "b")
    .flatMap(s -> Observable.from(s.toUpperCase(), s + s))
    .subscribe(System.out::println);
```

### Смена потоков выполнения

```java
import ru.yartsev_vladislav.rx.schedulers.Schedulers;

Observable.from(1, 2, 3)
    .subscribeOn(Schedulers.io())
    .observeOn(Schedulers.single())
    .map(n -> n * 10)
    .subscribe(System.out::println);
```

### Отмена подписки

```java
Disposable d = Observable.from(1, 2, 3).subscribe(System.out::println);
d.dispose();
```
